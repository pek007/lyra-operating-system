Status: Active
Owner: Peter + Lyra

## Two-loop learning model (mandatory)
All feedback and retrospectives must classify learnings into two loops:

## Loop A — OS Loop (generic learning)
Applies across projects and becomes part of Lyra OS.

Examples:
- prompting standards
- 3PP handoff quality rules
- test/verification discipline
- risk controls
- process anti-patterns

Where to update:
- OS-level process/prompt/governance docs
- reusable templates/checklists

## Loop B — Project Loop (local learning)
Applies only to a specific project (e.g., control panel).

Examples:
- feature-specific UX issues
- project data model refinements
- project route/contract adjustments
- project backlog priorities

Where to update:
- project docs/backlog/retro/closeout files

## Classification rule
For each miss/retro item:
1. Is this reusable across future projects? -> OS Loop
2. Is this specific to one product/context? -> Project Loop
3. If both, create two actions (one in each loop).

## Execution requirement
A retrospective is not complete until:
- at least one OS-loop assessment is made, and
- project-loop actions are separated from OS-loop actions.

## Verification
At next sprint planning:
- check OS-loop actions were incorporated into OS docs/templates
- check project-loop actions were incorporated into project plan/backlog
