# Closed-Loop Improvement Checklist v1

Use this when a meaningful issue, review finding, incident, or improvement opportunity appears.

---

## 1) Signal
- What happened?
- Why does it matter?

## 2) Classification
- Type: incident / near miss / control failure / process failure / decision failure / improvement opportunity
- Scope: product-local / cross-product / system-level
- Owner:
- Nature: execution / model / interface / governance / delivery-mode / other

## 3) Assignment
- What corrective action is required now?
- What task/decision/report is created?
- Who owns it?

## 4) Structural update
- Which artifact or control layer must change?
- Product-local or shared?

## 5) Verification
- How will we know the fix worked?
- What evidence or review will confirm closure?

## 6) Retention
- Where does the durable learning live?
- What should future-us read to avoid repeating this?

## 7) Completion check
- [ ] action assigned
- [ ] artifact/control updated
- [ ] verification path defined
- [ ] learning retained
