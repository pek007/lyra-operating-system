# STD-001: Definition of Done

## Purpose
Set a clear quality threshold for when a task is truly complete.

## Definition of Done (DoD)
A task is **Done** only when all applicable criteria are met:

1. **Deliverable complete**
   - Requested output or action is fully delivered.

2. **Assumptions documented**
   - Key assumptions/constraints are explicitly noted where relevant.

3. **Decision/next step clear**
   - Either a concrete next step exists, or task is explicitly closed.

4. **Documentation updated**
   - If process/policy/decision changed, relevant docs are updated.

5. **Storage/location correct**
   - Final artifact is stored in the correct canonical location.

6. **Risks addressed**
   - Any residual risks are stated and accepted.

## Additional Criteria for High-Stakes Outputs
For client-facing or high-impact items:
- Reasoning quality reviewed
- Source quality checked (when applicable)
- Language clarity and professionalism confirmed

## Not Done If
- Output is partial without explicit agreement
- Critical assumptions are hidden
- No owner/next step for unresolved issues
- Artifacts are only in chat and not stored where needed
