# Activation — Interfaces v0.1

## Purpose
Activate the Interfaces v0.1 assembly in a consuming environment so prompt contracts, model-routing discipline, and provider/tool workflow guidance become a real part of execution rather than background reference material.

## Activation rule
This assembly is only active when:
1. the packaged artifacts are present through a known distribution lane
2. one real or representative workflow uses the relevant contract/guidance artifacts
3. a model-routing rationale is recorded where applicable
4. verification evidence is produced

## Supported activation lanes
### Preferred lane
- version-pinned assembly distribution into the consumer workspace

### Temporary lane
- controlled interim copy lane while pinned distribution is not yet active

## Activation steps
1. Install the Interfaces assembly through the approved lane.
2. Record the installed version/lock entry in the consumer scope.
3. Select one real or representative downstream workflow.
4. Use the relevant prompt contract / routing discipline / provider workflow guidance for that workflow.
5. Record any non-default model-routing rationale.
6. Run `VERIFY.md` and capture the evidence link.

## Minimum evidence expectations
A valid activation should produce evidence covering:
- distribution lane used
- installed version / lock reference
- workflow tested
- interface artifacts used
- model-routing rationale if relevant
- pass/fail outcome
