# TDE UI Pilot Delivery Contract v1

Status: Draft active
Owner: Lyra (Delivery)
Date: 2026-03-12
Related pilot: `ONE_ITERATION_TDE_UI_PILOT_V1.md`

## Purpose
Define the minimum Delivery-side contract for the One-Iteration TDE UI Pilot.

The goal is to make the pilot strict enough to count as professional delivery, while light enough to remain feasible as a one-iteration proving slice.

## Delivery intent
Delivery will treat this pilot as one bounded Delivery Unit with explicit gate logic.

The pilot should move through:
1. objective and scope confirmation,
2. bounded implementation execution,
3. verification evidence capture,
4. explicit release/readiness judgment,
5. post-pilot review.

## Smallest viable delivery shape
The smallest viable Delivery shape is:
- one approved pilot objective,
- one bounded first slice,
- one explicit implementation path,
- one explicit verification path,
- one explicit release/readiness decision,
- one post-pilot review.

Delivery does not require a large project structure to start.
Delivery does require that the chain from scope -> implementation -> evidence -> release decision is explicit.

## Minimum acceptable production bar
For this pilot, Delivery defines “production” as:
- deployed in a real runtime/environment,
- usable for one narrow real operator purpose,
- not just a mockup or local-only throwaway,
- protected by an explicit readiness/release decision,
- low-blast-radius and reversible if the slice proves weak.

## Minimum evidence set
The minimum evidence set for this pilot is:
1. scope/non-goals record,
2. implementation evidence,
3. verification evidence,
4. release/readiness decision artifact,
5. post-pilot review note.

## Early gate questions
Before implementation proceeds too far, Delivery needs clear answers to:
1. What exact operator problem does the first GUI slice solve?
2. What is the smallest acceptable production meaning of the slice?
3. What is explicitly out of scope for iteration one?
4. What evidence is required before release?
5. What rollback or low-risk containment exists if the slice is weak?

## Main delivery risks
- scope inflation before a smallest slice is fixed,
- production being defined too loosely,
- evidence requirements being too vague,
- readiness judgment being implied instead of explicit,
- cross-product handoff staying informal.

## Current recommendation
Proceed, but only with:
- fixed smallest-slice scope,
- explicit evidence expectations,
- explicit release/readiness decision,
- post-pilot review as part of the pilot rather than afterthought.
