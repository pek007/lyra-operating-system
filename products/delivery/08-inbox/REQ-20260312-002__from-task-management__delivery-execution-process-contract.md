# Request — Delivery Execution Process Contract for Objective-to-Production Pilot

Request ID: REQ-20260312-002
Date: 2026-03-12
From product: Task Management (`A-007`)
To product: Delivery (`A-006`)
Requested by: Lyra
Status: proposed
Urgency: high

## Purpose
Request a Delivery-defined execution process contract for how a high-level objective enters and moves through governed Delivery execution.

## Requested outcome
Provide a bounded Delivery artifact that explains, in practical process terms:
1. the end-to-end Delivery process flow,
2. the toll-gates and required pass conditions,
3. what gets documented where,
4. who the stakeholders are,
5. stakeholder responsibilities,
6. where the decision points are,
7. how a new project / Delivery Unit is set up,
8. how Task Management / TDE, Delivery, approver(s), and execution lanes interact.

## Why this request exists now
Task Management is preparing to instantiate the new Objective Start Gate for the TDE UI pilot.

Before doing that, the receiving Delivery process needs to be explicit enough that the objective packet is not handed into an underspecified downstream operating model.

In short:
- we now know what information an objective should contain,
- but we still need Delivery to define the process that receives and governs it.

## Decision needed
Yes.

Primary decision requested from Delivery:
- What is the practical Delivery execution process contract that should govern a bounded objective-to-production application effort in the current Lyra OS model?
