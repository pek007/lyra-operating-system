# Customer

## Customer model
Task Management is currently an internal enabling product, so its "customers" are primarily internal operators and downstream consuming workspaces rather than external buyers.

## Primary customers
### 1. PX Strategy operating system / Lyra OS
Needs:
- reliable execution flow
- visible task state
- explicit decisions and blockers
- less dependence on chat memory and ad hoc coordination

### 2. `pxs` workspace
Needs:
- a usable downstream task/decision capability
- clear interfaces and operating expectations
- low-friction adoption
- confidence that the product is reliable enough for practical use

## Secondary customers
### Internal agents and future product owners
Need:
- explicit product boundaries
- a stable operational system of record
- reusable patterns for managing work and decisions

## Jobs to be done
Customers use this product to:
- keep meaningful work visible
- move work from intent to execution reliably
- record decisions with enough context to act and review later
- reduce coordination failure, ownerlessness, and dropped work
- create an execution system that compounds rather than resets each session

## Adoption requirement
Customers will only keep using Task Management if it feels meaningfully better than loose chat coordination and scattered notes.

## Current customer promise
Task Management should make work easier to run, easier to inspect, and easier to improve over time.
