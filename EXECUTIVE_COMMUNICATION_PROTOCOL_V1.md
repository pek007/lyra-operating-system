# EXECUTIVE_COMMUNICATION_PROTOCOL_V1.md

Status: Active (v1)
Owner: Peter (A), Lyra (R)

## Purpose
Standardize executive communication so process rigor is preserved while updates remain easy to act on.

## Default output format (all strategic/process/project updates)

### 1) Executive view
- Where we are (plain words)
- Why this matters now
- Decision needed from Peter (if any)
- Recommended move
- Risk of waiting

### 2) Technical appendix (short)
- 5–10 bullets
- key concepts, assumptions, and constraints
- concise terminology for learning context

## Style rules
- No color-status shorthand.
- Prefer plain language over process jargon.
- Keep process terminology internal unless needed for a decision.
- Include process terms in appendix only when useful.

## When mandatory
- Sprint/gate updates
- Major architecture/process changes
- Go/no-go recommendations
- Risk/escalation updates

## Exceptions
- Simple confirmations can be short-form.
- If Peter requests raw technical detail first, provide it and append executive summary.
