# SOP-001: Intake & Triage

## Purpose
Ensure every incoming request is captured, prioritized, and moved into execution with clear ownership and next steps.

## Scope
Applies to all new requests/tasks for Lyra + Peter.

## Workflow States
- **Inbox**: Newly captured, not yet assessed
- **Triage**: Being clarified/prioritized
- **Active**: In execution now
- **Waiting**: Blocked or awaiting input
- **Done**: Completed per Definition of Done
- **Archived**: Closed and no longer active

## Priority Levels
- **P1 Critical**: High impact + urgent, immediate handling
- **P2 Important**: High impact, planned in near-term
- **P3 Normal**: Standard work item
- **P4 Nice-to-have**: Low urgency/impact

## Intake Rules
1. Every request gets captured as a task item.
2. Minimum fields on intake:
   - Title
   - Requestor (usually Peter)
   - Date captured
   - Target outcome
   - Initial priority (P1–P4)
3. If request is ambiguous, capture assumptions and move to Triage.

## Triage Cadence
- Daily 10-minute triage pass.
- For each item in Inbox/Triage:
  1. Clarify objective
  2. Estimate effort (S/M/L)
  3. Confirm priority
  4. Assign next action
  5. Move to Active/Waiting/Backlog

## Escalation Rules
Escalate immediately to Peter when:
- Potential security/privacy risk
- External action with reputational or legal implications
- High-cost tool/service decision
- Conflicting priorities requiring executive trade-off

## Service Expectations (initial)
- Acknowledge new P1/P2 requests promptly.
- Place all requests into a visible state same day when possible.
- Provide explicit next step for every Active/Waiting task.

## Output Standard for Task Updates
Each significant update should include:
1. What changed
2. Current status
3. Risks/blocks
4. Next step + owner

## Quality Control
A task cannot move to Done unless STD-001 (Definition of Done) is satisfied.
